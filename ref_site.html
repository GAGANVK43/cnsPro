WHAT THIS MODELS

MITM risk is about trust, not just Wi‑Fi.

An adversary may try to position themselves between a device and service. Encrypted connections, certificate validation, request integrity, and payment authorization make that position far less useful.

These interactive modules show the building blocks behind a protected payment session. All cryptographic actions run locally in the browser using fictional content.

MODULE 05 · KEY AGREEMENT

Diffie–Hellman exchange

Two endpoints derive the same shared secret without sending that secret across the network.

PUBLIC VALUES → p=23, g=5
EXCHANGED VALUES → A=8, B=19
SHARED SECRET → 2 ✓ match
  1. 01Aarav calculates A = ga mod p = 56 mod 23 = 8 and shares only A.
  2. 02UPI switch calculates B = gb mod p = 515 mod 23 = 19 and shares only B.
  3. 03Aarav derives Ba mod p = 2; the switch derives Ab mod p = 2.
  4. 04Both sides now have the same secret, which can seed a symmetric encryption key.

Uses small, readable values for education only; production systems use modern elliptic-curve key exchange.

MODULE 07 · INTEGRITY

SHA‑256 hashing

A hash creates a fixed fingerprint. Any edit to the message produces a completely different result.

c61b716141db973a9843c14f12a44cefe1ece94e8c367753e36ee8bf0124cd05

SHA‑256 is one-way: it verifies data integrity but cannot decrypt a message.
